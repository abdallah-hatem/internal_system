`17f4d39` (record_sale).

## What was built

- **One matcher**, `receipt/name-matching.ts` → `matchByName(query, items, kind)`. Token-based:
  case, punctuation, plurals (`singular`: pads→pad, boxes→box), word order, extra descriptor
  words, and a one-slip misread. Returns `matched` / `several` / `close` / `unknown` with ranked
  candidates (max 5, never scored 1 unless exact). **Only the id, an exact SKU or an exact
  normalised name is `matched`**; anything weaker is a candidate. A name is offered when it shares
  ≥ 2/3 of the shorter name's words, or its whole-name similarity is ≥ 0.8. Suppliers use it with
  their legal-form words dropped; `analyzeReceipt`'s own product and supplier matchers are now thin
  adapters onto it (the "contains a product's name → matched" step is gone).
- **`record_sale`** (`tools/sales.ts`), registered in `assistant-server.ts`, `SalesModule` imported
  into the assistant module. Input `{customer?, walkIn?, lines:[{product, qty, unitPrice?,
  discount?}], paymentMethod?}`.
  - `resolveSale` (pure) matches the customer (walk-in record excluded) and each product. Anything
    unsettled — `CUSTOMER_WHICH`, `CUSTOMER_UNKNOWN` (offers "a walk-in sale"), `LINE_WHICH` with
    candidates, `LINE_UNKNOWN`, `PRICE_NEEDED` — comes back as questions.
  - `tool-kit.ts` gained `ToolOutcome.needsAnswers`: such a preview returns `status:
    "needs_answers"` with the questions and **no confirmation token**, so nothing about it can be
    committed.
  - No price → the open list price on the buyer's channel (`portal-pricing.priceOn`; the customer's
    type, B2C for walk-in), marked `list price — confirm or give the price`.
  - Preview = `SalesService.create` (walk-in path or create-and-confirm) run on `rollingBack`'s
    database, so every refusal is the service's own; it shows lines, price source, line totals,
    stock available per line, the total, the status after, and for walk-in "Paid on the spot by
    <method>". Commit = the same `SalesService.create`, for real. No rule is restated in the tool.
  - Binding: customer, each line's product / qty / price / discount / line total / available, and
    the total.
- `instructions.ts`: a "Recording a sale" paragraph; the "what you can change" list now names it.
- No new error codes (`VALIDATION_FAILED`, `PREVIEW_CHANGED` and the sales refusals are reused).
