and `48e1123` (web, docs). The decision is the owner's (2026-10-10, BUSINESS_LOGIC
roles).

## The scope helper

`apps/api/src/common/investor-scope.ts` — the one definition every read uses
(rule 11).

- `cyclesVisibleTo(viewer, db)` → `null` for CORE_PARTNER and ADMIN_SUPPORT (every
  cycle); for TEMP_INVESTOR the ids of the cycles they participate in (a
  `CycleParticipant` row naming them as investor, or partner); `[]` for any other
  role or no user — it fails closed.
- `'internal'` is an explicit viewer for the assistant (core partners only), which
  calls service reads directly. Service read methods default to it; every
  controller passes `@CurrentUser()`, and a spec checks each one does.
- `ownParticipantIds` / `participantFilter` — the viewer's own participant rows,
  for reads that show a line per participant.
- `assertInScope(scope, cycleId, entity)` → `NOT_FOUND` (404, not 403, so asking
  does not confirm a cycle exists). `cycleIdWhere(scope, requested)` narrows a
  list's `cycleId` filter; a cycle asked for outside the scope matches nothing.

No new error codes: refusals are `ROLE_NOT_ALLOWED` (the guard's) and `NOT_FOUND`.
