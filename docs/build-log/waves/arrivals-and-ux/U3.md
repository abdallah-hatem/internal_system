# U3 — App shell: no search, a phone bottom bar

Branch `feature/ux-u3`, from `b571e63`. Spec A #6, #9 and the quick win "the back link is at least
44px tall".

## What changed

- **Search box removed** from the top bar. It was never wired to anything. The header now holds
  only the language switch, the bell and the user, pushed to the end with `ms-auto`.
- **Phone bar** (`components/layout/phone-bar.tsx`), below `md` only: Dashboard, Sales, Customers,
  Inventory, Cycles, More. Fixed to the foot at z-30, so modals (z-50) and the open drawer cover
  it. Every target is 56px tall, padded by `env(safe-area-inset-bottom)`, active by
  `aria-current`. "More" opens the existing grouped drawer and is lit while it is open or on a
  page the bar does not reach. Its order follows `dir`, so under Arabic Dashboard sits at the
  right-hand edge.
- The hamburger is now `md`–`lg` only. On a phone, "More" replaces it.
- `<main>` is padded at the bottom by the bar's height plus the inset below `md`. The shell is
  `h-dvh`, not `h-screen`: on a phone `vh` is the height with the address bar hidden.
- `viewport` export in `[locale]/layout.tsx` with `viewportFit: 'cover'`. Without it every
  `env(safe-area-inset-*)` reads 0. Zoom stays allowed.
- **Nav model** (`components/layout/nav-model.ts`): the menu's groups, hrefs and an optional
  `roles` per entry, plus `navForRole`, `systemForRole` and `phoneBarItems`. The sidebar, "More"
  and the bar all read it, so they cannot disagree. Icons stay in the shell.
- **`BackLink`** (`components/ui/back-link.tsx`) replaces four copies of the inline back button
  (customer, cycle details, product ×2). It is 44px tall. A `-mt-3`/`-mx-2` gives most of that
  space back to the layout, so it looks as it did. The arrow flips under RTL.
- Locale keys, `nav` only: `more`, `phoneBar`, `openMenu`, `closeMenu`, `short.{dashboard, sales,
  customers, inventory, cycles}`. "Import Cycles" is too long for a fifth of a phone, so the bar
  says "Cycles" / "الدورات".

## Role filtering: a finding

The brief said the bar should respect the role filtering the sidebar already applies. **The
sidebar applies none.** Every signed-in role sees all 22 entries. Whether that is right is a
business question this task does not settle. Instead, `roles` on an entry now narrows the
sidebar, "More" and the bar together, and no entry carries a restriction, so nothing a user sees
has changed. *Open:* which roles (investor, shop) should see which entries. That decision belongs
in `docs/BUSINESS_LOGIC.md`.

## Tests

- `apps/web/unit/nav-model.test.mjs`, run with `npm run test:unit` (Node's own runner). The web app
  has no Vitest or RTL, and adding them was out of scope. 10 cases: the bar's order; every bar key
  being a real menu entry; "More" holding all 22; an investor not being offered a hidden entry;
  the bar always being a subset of the role's menu; an emptied group disappearing; a loading
  (undefined) role and an unknown role seeing only unrestricted entries; segment-exact active
  state; "More" lit only off-bar. Revert check: making `phoneBarItems` ignore the role fails 4
  of them, and restoring it passes all 10.
- `apps/web/tests/74-phone-nav.spec.ts` (Playwright, **not run here**): at 390×844 the bar is
  visible and Sales is reached by tapping it; it holds exactly the six entries; every target is
  ≥ 44px; "More" opens the grouped menu, and a link in it navigates and closes it; "More" a
  second time; the last element of a page scrolls clear of the bar; the order mirrors in Arabic;
  no bar on desktop; no search input at either size; the back link is ≥ 44px.
- `tests/12-cross-cutting.spec.ts` TC-XCUT-15 used to assert that the search box exists. It now
  asserts the header has no input.
- `eslint-suppressions.json` pruned. The raw-colour counts dropped where the old back buttons
  and the search input went.

## Needs a phone

The safe-area padding and the `dvh` height can only be confirmed on real hardware: an iPhone with
a home indicator, in Safari and installed.
