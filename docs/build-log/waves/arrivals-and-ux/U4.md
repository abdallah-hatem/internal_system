# U4 — Dashboard you can act from

Branch `feature/ux-u4-dashboard`, from `d62a531`, rebased onto master after U4b
merged (`8abfc53`).

## What changed

- **Quick actions** at the top: New sale → `/sales?new=1`, Record payment →
  `/payments?new=1`, New cycle → `/cycles/new`. The first two land on the list
  page and open its own create form (`useOpenFromQuery`, `lib/open-from-query.ts`);
  no form is copied. The parameter is dropped once used, so a refresh does not
  reopen a form the user closed, and arriving with it again opens it again.
- **Tiles are links**, the whole card, ≥44px, two columns on a phone:

  | tile | opens |
  |---|---|
  | Revenue | `/sales` |
  | Collected | `/payments` |
  | Receivables | `/customers?sort=balance` (largest balance first) |
  | COGS, Net profit | `/analytics` |
  | Expenses, Cash out, Cash on hand | `/ledger` |
  | Active cycles | `/cycles` |
  | Inventory value | `/inventory` |
  | Low stock | `/inventory?stock=low` |

- **Recent activity** reads `GET /analytics/recent-activity?limit=10` (U4b),
  renders `occurredAt` through `useDateFormat`, translates `kind`, the order
  status and the payment method, shows `EmptyState` when empty and a message on
  error. Refetched on every visit (`staleTime: 0`, `refetchOnMount: 'always'`)
  so a sale confirmed elsewhere shows after clicking back; recording or
  reversing a payment now invalidates `['analytics']` too.
- **Roles** come from one table, `components/dashboard/dashboard-model.ts`,
  mirroring the API guards: quick actions and the activity panel are hidden
  from roles the API refuses; a tile whose list the role cannot open is a plain
  tile, not a link to a 403.

## Guesses and gaps

- **Low stock uses the dashboard count's rule** (`isBelowMinStock`: active,
  minimum set, on-hand < minimum), not the inventory page's own red highlight
  (any batch under 10). The two disagree; the filter matches the number on the
  tile. A product with a minimum but no batch at all is counted by the
  dashboard and cannot appear in inventory (the list is built from batches).
- Receivables sorts the customers page's existing 200-row fetch client-side.
- No browser check was run (no dev server started); Playwright cases are
  written, not run.
