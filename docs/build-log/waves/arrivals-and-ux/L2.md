# L2 — One definition of "low stock"

Branch `fix/l2-one-low-stock`, based on `2739ac0`. Rule: BUSINESS_LOGIC §3 (DECIDED 2026-10-10,
"one meaning of low stock"); CLAUDE.md rule 11. Found by the release review.

## The copies, and how they disagreed

| Where | Before |
|---|---|
| `analytics.service.ts` dashboard count | ACTIVE, minimum set, Σ `remainingQty` < minimum — correct |
| `inventory.service.ts` alert on receiving | `if (product?.minStock)`, Σ `saleableQty`, **inactive products included** |
| `web/components/dashboard/list-params.ts` `isBelowMinStock` | right rule, its own copy |
| inventory page filter + highlight (F1a) | imported the list-params copy |

## Decision

**Stock on hand = `remainingQty` summed over every batch**, not `saleableQty`. A unit held for a
customer is still on the shelf, and a minimum is a reorder point for the shelf. Today the two are
equal (nothing holds stock — §3); fixing one now is what keeps them from drifting the day something
does. Written into BUSINESS_LOGIC §3 under the existing decision.

## What changed

- **`apps/api/src/common/low-stock.ts`** — the one definition: `isLowStock(product, onHand)`,
  `stockOnHand(batches)`, `findLowStock(db, productIds?)` (DB narrows to ACTIVE + minimum set, the
  predicate decides) and `countLowStock(db)`. No value imports, so the web test loads it as is.
- Dashboard count → `countLowStock(this.prisma)`.
- Receiving alert → `findLowStock(tx, productIdsOfTheReceipt)` once, after every line is in. Side
  effects: an inactive product no longer alerts; two lines of one product give one alert with the
  final figure (the old per-line check could push the same product twice).
- **`apps/web/src/lib/low-stock.ts`** — the one web copy (`isLowStock`, `stockOnHand`,
  `isBelowMinStock`). The inventory page imports it; `list-params.ts` re-exports `isBelowMinStock`
  from it rather than defining it.
- Test fakes (`shipment-fake-spec.ts`, `assistant/tools/cycle.spec.ts`) answer `product.findMany`,
  applying the `where` they are sent.

## Tests

- `apps/api/src/common/low-stock.spec.ts` — predicate (below, exactly at, no minimum, inactive,
  minimum 0, decimals as text, junk minimum), several batches summed, remaining not saleable, the
  query agrees with the predicate per product, and the dashboard count through
  `AnalyticsService.getDashboardKPIs` (7 products → 3).
- `apps/api/src/modules/inventory/low-stock-alert.spec.ts` — the receiving alert: below → one alert
  with the figure; inactive, no minimum, exactly at → none; 12 on the shelf + 5 received against 15 →
  none (batches summed across cycles).
- `apps/web/src/lib/low-stock.test.ts` — the web copy against the API file over a 17-case table, plus
  `stockOnHand` and `isBelowMinStock` rows.

**Revert checks (rule 2).** The old `inventory.service.ts` (`if (product?.minStock)`, saleable) put
back → "an inactive product is never low" fails (1 of 5). The web copy changed to `<=` → 6 of 35 fail.
The dashboard count was already right, so its test passes against the old code too — it pins, it
does not reproduce.

## Not changed — a different question

The shop portal's stock band (`available-stock.ts` `stockBand`: LOW at ≤ 5 *available*, holds
deducted) also says "low". It answers what a shop is told, not when to reorder, and §12's "stock is a
band" decision owns it. Left alone; worth naming differently if the two are ever confused.
