# B3 — Receiving per delivery, fixed unit cost, settlement gate

Branch `feature/arrivals-b3`, code commit `5c08848` (based on `2e18c40`).

## What was built

- **`POST /receipts/verify`** `{cycleId, deliveryId, items:[{deliveryLineId, receivedQty,
  landedUnitCostEgp?}]}`, CORE_PARTNER, now with a DTO (`inventory/dto/verify-stock.dto.ts`,
  shape only; every rule is in the service). Allowed in ARRIVED_EGYPT / VERIFICATION / SELLING;
  earlier `CYCLE_NOT_ARRIVED`, SETTLEMENT/CLOSED `CYCLE_SETTLING`, CANCELLED `CYCLE_CLOSED`.
  A delivery of another cycle is `notFound('shipmentDelivery')`, a line of another delivery
  `notFound('shipmentDeliveryLine')`, a leg-1 delivery `NOT_LAST_LEG_DELIVERY`. A delivery line
  is received in several goes, capped at `min(qty − received from it, the line's waiting)`
  (`RECEIVED_EXCEEDS_DELIVERED` {product, received, available}); nothing left on it
  `STOCK_ALREADY_VERIFIED`. A zero line is skipped (no batch); negative qty `QTY_NOT_POSITIVE`;
  negative cost `VALIDATION_FAILED`. One batch per line with `sourcePoItemId`,
  `sourceDeliveryLineId`, `arrivedOn` (the delivery's).
- **Under the lock.** `verifyStock` takes `lockCycle`, re-runs every check in the transaction,
  then walks the cycle on: each step is `CyclesService.transitionIn(tx, …)` =
  `planTransition(…, {db: tx})` + its writes, so each step's checks and side effects run, and
  a refused step rolls the whole receipt back. Audit/notifications for the steps go out after
  the commit (`announceTransition`).
- **Old body** (`purchaseOrderItemId`, no `deliveryId`): uses the one last-leg delivery line of
  that order line still waiting; two or more → `DELIVERY_REQUIRED` {product, deliveries}; all
  received → `STOCK_ALREADY_VERIFIED`; nothing delivered → `RECEIVED_EXCEEDS_DELIVERED`
  (available 0). `giveStock` / `stockedProduct` work unchanged (PUT arrivedOn → B2 delivery →
  old body), checked in a unit test and against a running API on a throwaway database.
- **Cost per ordered unit** (`costing.service.ts`): `computeCycleLandedCosts` always allocates
  over ordered quantities (`qtyOverrides` removed); unit = line landed total ÷ ordered, 4 dp.
  `lineEventCost` (pure, same file): an event costs `round2(qty × unit)`; the event that makes
  received + lost = ordered costs `landed total − Σ round2(earlier batch qty × unit) − Σ earlier
  loss costs`, and stores that ÷ qty (4 dp) as its unit. Earlier batches count at the standard
  unit, so a manual override stays on its own batch. B2's loss valuation uses it too. Ledger
  PURCHASE_COST per receipt = the event cost. `GET /costing/…/landed-cost` adds `orderedQty`
  and `basis: 'ordered'`.
- **`receivedQty`** = aggregate of the line's batches, written in the receipt transaction.
  `PUT /purchases/items/:id` with `receivedQty` → `VALIDATION_FAILED` {fields: receivedQty}
  (in the service); without it, a no-op returning the line.
- **Settlement gate**: `common/shipment-accounted.ts` `assertShipmentAccounted(db, cycleId)` →
  `SHIPMENT_NOT_ACCOUNTED` {cycle, onTheWay, waiting, lines}. Called in `planTransition` for →
  SETTLEMENT and in settlement `approve` (inside its transaction, after `lockCycle`).
  `transition` now always runs plan + writes inside one transaction holding `lockCycle`
  (B2 carry-over 3 / B2 guess 10). Nothing ordered → accounted.
- **Losses in profit**: settlement `project` adds `cycleLossesEgp` to expenses; `calculate` now
  reuses `project` (it was a verbatim copy); `preview`/`calculate` report `lossesEgp`.
  Analytics cycle profitability subtracts it per cycle (`lossesEgp` field) and the dashboard's
  net profit subtracts it for all cycles (`cycleLossesEgp(db, null)`). No ledger rows.
- **Arrival per batch**: `GET /inventory` (which the product page reads) returns the batch's own
  `arrivedOn`, falling back to the last dated leg only when it is null.
- **Seeds**: the demo's two cycles get dated, departed legs and one full delivery per leg
  (`deliverInFull`), batches linked to the last-leg delivery lines with their date. Reference has
  no cycles. The S1 payments-through-PaymentsService path is untouched. Seed formatted by
  `eslint --fix` (its 84 frozen prettier errors pruned).
- **check-data**: 12.5 allows a loss off `round(qty × unit, 2)` only when it is the line's final
  event (line accounted, nothing on it recorded later) and within the 4-dp rounding. New 12.7
  "a delivery line received more than it brought".
- **Codes**: added `CYCLE_NOT_ARRIVED`, `NOT_LAST_LEG_DELIVERY`, `DELIVERY_REQUIRED`,
  `RECEIVED_EXCEEDS_DELIVERED`, `SHIPMENT_NOT_ACCOUNTED`, entity `shipmentDeliveryLine`;
  `STOCK_ALREADY_VERIFIED` reworded with {product}; removed `CYCLE_NOT_IN_VERIFICATION` and
  `RECEIVED_EXCEEDS_ORDERED` (nothing throws them). en + ar.
- **Assistant `verify_stock`**: only a type fix (`sourcePoItemId: string | null`) and
  `InventoryService`'s new `CyclesService` argument in the specs. Its description still says
  "VERIFICATION … once" — B4 rewrites it. `tools/read.ts`' `get_stock` description still says
  arrival is the last leg (B4 owns that file).
- `scripts/stock-products.mjs`: no longer transitions to SELLING after verifying (the receipt does).

## Guesses (open until confirmed)

1. **A receipt whose every quantity is zero is refused** (`QTY_NOT_POSITIVE`); a zero line beside
   real ones is skipped. Keeps the assistant's "0 → refused" and "0 → no batch".
2. **Old body with nothing delivered → `RECEIVED_EXCEEDS_DELIVERED` (available 0)**, not
   `DELIVERY_REQUIRED` — there is no delivery to name.
3. **The residual counts earlier batches at the standard unit**, not their typed override.
4. **The dashboard's net profit subtracts losses too** (§9 says "on the settlement and on the
   dashboard"); `cycleLossesEgp(db, null)` = all cycles, still one definition.
5. **`calculate` now reads `project`** — same arithmetic, removed a duplicate.
6. **`PUT /purchases/items/:id` without `receivedQty` is a no-op** returning the line.
7. **`SHIPMENT_NOT_ACCOUNTED.onTheWay` counts everything neither received, lost nor waiting**, so
   a cycle whose legs were never recorded still reports its units.
